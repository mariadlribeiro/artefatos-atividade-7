1. Identificação e visão geral
O IoT-ID é apresentado como um protótipo para identificação determinística de dispositivos IoT por meio de características híbridas de rede. A proposta combina sondagem ativa, captura passiva de pacotes, extração de características TCP/IP, normalização dos atributos e geração de uma impressão digital utilizando SHA-256. Documentação dos autores.

O fluxo documentado contém sete etapas:
1. Varredura ativa com Nmap.
2. Captura de pacotes com dumpcap.
3. Sondagem TCP SYN com Nping.
4. Identificação passiva com p0f.
5. Extração de características com TShark.
6. Canonicalização das características.
7. Geração do hash SHA-256.
A proposta é interessante porque procura identificar dispositivos mesmo quando seus endereços IP mudam ou ocorre randomização de endereços MAC. Entretanto, essa alegação precisa ser diferenciada da capacidade de identificar unicamente cada dispositivo físico: equipamentos do mesmo modelo podem produzir a mesma impressão digital.

A análise do código identifica uma implementação organizada em módulos, com responsabilidades distintas.

O processamento utiliza informações provenientes de três fontes principais:
- Nmap/UPnP: fabricante, modelo e informações do dispositivo.
- p0f: características passivas do sistema TCP/IP.
- TShark: extração de características dos pacotes capturados.
Posteriormente, os dados passam pela canonicalização, que organiza os atributos de maneira determinística. A representação resultante é utilizada para gerar o SHA-256.

Aspectos positivos identificados no código:
1. Separação das responsabilidades em módulos.
2. Normalização de espaços e ordenação de listas.
3. Serialização JSON com ordenação das chaves.
4. Tratamento de informações ausentes.
5. Registro de logs e tempos de execução.
6. Geração de arquivos de saída para inspeção posterior.
7. Existência de alternativas de extração quando determinadas características não estão disponíveis.
Um aspecto importante é que o código contempla dois tipos de identificação: dispositivos IoT com informações UPnP e equipamentos classificados como mobile, que utilizam outro conjunto de características.

Limitações identificadas:
- A obtenção de características depende do comportamento dos dispositivos e da disponibilidade de tráfego.
- A identificação por UPnP depende de os equipamentos fornecerem informações suficientes.
- A captura passiva depende de condições adequadas da interface de rede.
- A execução exige ferramentas externas e privilégios elevados.
- O código registra a execução do Nping sem verificar diretamente seu código de saída no fluxo principal (check=False). Isso reduz a capacidade de distinguir uma sondagem bem-sucedida de uma tentativa que apresentou falha.
Também é importante observar que o próprio conceito de impressão digital não garante identificação individual de cada unidade física. Os autores mostram que dispositivos de mesmo modelo podem produzir hashes iguais.

Conclusão F: a implementação apresenta os componentes necessários para realizar a funcionalidade proposta e possui tratamento para diferentes cenários de coleta. Entretanto, a funcionalidade completa não foi comprovada por execução independente nesta avaliação.
